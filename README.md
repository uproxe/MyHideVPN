# vless-setup

Пошаговый мастер, который с нуля поднимает личный VPN на **VLESS + REALITY + XHTTP** на одном или двух своих серверах.

Мастер — один bash-файл. Его запускают на своём компьютере и отвечают на вопросы, а он по SSH сам настраивает серверы и в конце выдаёт ссылку `vless://…` и мини-панель управления.

## Схемы

Первым вопросом мастер спрашивает, сколько будет серверов.

**Один сервер**

```
клиент ──► сервер ──► Cloudflare WARP ──► интернет
              └──► российские сайты — напрямую с сервера
```

Сервер может стоять за границей или в России. Если сервер в России, клиент подключается к российскому IP, а заблокированные сайты открываются через WARP.

**Два сервера** — устойчивее к блокировкам

```
клиент ──► российский сервер (вход) ──► зарубежный сервер ──► Cloudflare WARP ──► интернет
                  └──► российские сайты — напрямую с российского сервера
```

Клиент видит только российский IP. IP зарубежного сервера не светится ни перед провайдером, ни перед сайтами, на которые вы заходите.

## Что нужно

- **Серверы:** 1 или 2 VPS с Debian 12/13 или Ubuntu 22.04+ (x86_64 или arm64), доступ root по SSH. Лучше чистые, но мастер умеет разбираться с занятыми портами.
- **Компьютер:** macOS или Linux с `bash`, `ssh`, `curl`. Windows подходит через WSL.
- **Домен:** бесплатный поддомен на [duckdns.org](https://www.duckdns.org) на каждый сервер или свой домен (см. ниже).
- **Клиент:** приложение или роутер с поддержкой транспорта XHTTP (ядро Xray 24.11 или новее).

## Быстрый старт

1. Скачайте `vless-setup.sh` со страницы [Releases](../../releases) и проверьте контрольную сумму:
   ```
   shasum -a 256 -c vless-setup.sh.sha256
   ```
2. На duckdns.org создайте по одному поддомену на каждый сервер (имена любые) и скопируйте токен со страницы аккаунта.
3. Запустите:
   ```
   bash vless-setup.sh
   ```
4. Ответьте на вопросы. Через несколько минут ссылка появится в терминале и в файле `vless-link.txt`.

## Что спросит мастер

| Шаг | Вопрос | По умолчанию |
|---|---|---|
| 1 | Один сервер или два | — |
| 2 | Для одного сервера — где он: в России или за границей | — |
| 3 | IP-адрес и SSH-порт каждого сервера | порт 22 |
| 4 | Токен DuckDNS и поддомен для каждого сервера | — |
| 5 | Сводка и подтверждение «Начинаем?» | да |

До подтверждения на серверах ничего не меняется. Порт VPN всегда 443, как у обычного сайта. Если 443 занят, мастер предложит другой.

## Если на сервере что-то занято

Перед установкой мастер проверяет порты и объясняет, что ему мешает:

- **Старый VPN** (x-ui, 3x-ui, xray, sing-box и т. п.) — предложит остановить его и отключить автозапуск.
- **Caddy на порту 80** — перенесёт его HTTP на 8080. Конфиг сохранится копией, при сбое мастер откатит изменения. nginx будет пересылать Caddy всё, что не относится к VPN, поэтому сайты на Caddy продолжат работать.
- **Другая программа на 443** — предложит выбрать другой порт для VPN.
- **Другая программа на 80** — остановится и объяснит, что порт нужен для сертификата.

## Как это устроено и почему

- **REALITY со своим доменом.** В TLS-рукопожатии указан ваш домен. Этот домен указывает на тот же IP, а на нём открывается обычный сайт с настоящим сертификатом Let's Encrypt. Кто зайдёт на сервер без ключа, увидит просто сайт. Чужое имя (например, известного сервиса) на случайном IP — признак, по которому VPN легко вычислить.
- **Сайт-заглушка у каждой установки свой.** Название, тексты, цвета и шрифт выбираются случайно, иначе все установки из этого репозитория выглядели бы одинаково. Можно положить свой сайт в `/var/www/decoy` — мастер его не тронет.
- **XHTTP** вместо постоянного TCP-соединения: трафик похож на обычные HTTP-запросы, соединения переиспользуются.
- **Отпечаток TLS Firefox** по умолчанию. Можно задать другой через `FP=chrome`.
- **Вход ≠ выход.** Адрес, к которому подключается клиент, не совпадает с адресом, с которого сайты видят ваш трафик (Cloudflare WARP).
- **DNS на серверах — только DoH** (Cloudflare, запасной — Google), и запросы идут через выход. Российские домены разрешаются на месте.
- **Разделение трафика.** Российские сайты идут напрямую с сервера-входа, остальное — через выход. Используются списки [runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat).
- **Самопроверка.** После установки сервер прогоняет трафик через весь путь: открывает зарубежный сайт, российский сайт и скачивает 8 МБ. Если зарубежный сайт не открылся или выход идёт не с того адреса, мастер останавливается и ссылку не выдаёт. Остальные проверки выдают предупреждения.

Гарантий, что VPN не заблокируют, нет: способы блокировки меняются. Мастер убирает самые заметные признаки.

## Повторный запуск и смена серверов

- Ответы сохраняются в `vless-setup.last` рядом со скриптом и подставляются по умолчанию в следующий раз. Запуск с `AUTO=1` вообще не задаёт вопросов, если все ответы уже есть.
- Повторный запуск на тех же серверах безопасен: ключи и сертификаты сохраняются, ссылка остаётся прежней.
- Если сервер заблокировали, возьмите новый VPS и запустите мастер снова, указав новый IP. Поддомен DuckDNS можно оставить старым — мастер перенаправит его.

## Панель

Мини-панель показывает ссылку и состояние, проверяет VPN, перезапускает Xray и меняет UUID (выдаёт новую ссылку). Наружу она не открыта: слушает только `127.0.0.1` на сервере-входе. Команду входа через SSH-туннель мастер печатает в конце, например:

```
ssh -p 22 -L 8088:127.0.0.1:8088 root@<IP сервера>
```

После этого панель открывается в браузере по адресу `http://localhost:8088`.

## Свой домен вместо DuckDNS

На вопросе о поддомене введите полный домен, например `blog.example.com`. Тогда DuckDNS не используется, а A-запись на IP сервера нужно один раз создать у своего регистратора. Свой домен выглядит обычнее, чем `*.duckdns.org`.

## Запуск без вопросов

Все ответы можно передать переменными:

```
MODE=1 S_LOC=foreign S_IP=203.0.113.10 S_SSH_PORT=22 S_SUB=myhome DUCKDNS_TOKEN=... AUTO=1 bash vless-setup.sh
```

| Переменная | Значение |
|---|---|
| `MODE` | `1` — один сервер, `2` — два |
| `S_IP`, `S_SSH_PORT`, `S_SUB`, `S_LOC` | один сервер: IP, SSH-порт, поддомен, `ru` или `foreign` |
| `RU_IP`, `RU_SSH_PORT`, `RU_SUB` | два сервера: российский вход |
| `RELAY_IP`, `RELAY_SSH_PORT`, `RELAY_SUB` | два сервера: зарубежный выход |
| `DUCKDNS_TOKEN` | токен DuckDNS |
| `CONN_PORT` | порт VPN (по умолчанию 443) |
| `RELAY_PORT` | порт между серверами (по умолчанию 443) |
| `EXIT_MODE` | `warp` (по умолчанию) или `direct` — выход с IP сервера, без WARP |
| `FP` | TLS-отпечаток: `firefox` (по умолчанию), `chrome`, `safari`… |
| `AUTO=1` | брать ответы по умолчанию, ничего не спрашивать |

## Ограничения

- Через WARP проходит только TCP: сайты, видео и мессенджеры работают, а зарубежные игры и звонки поверх UDP — нет.
- Нужен клиент с XHTTP. Старые клиенты ссылку не поймут.
- Для одного российского сервера нужен WARP. Если Cloudflare недоступен с сервера, мастер остановится и предложит другую схему.
- С российского сервера GitHub открывается не всегда. В схеме из двух серверов файлы передаются через зарубежный сервер, а для одного российского мастер пробует зеркала.

## Приватность

- `vless-setup.last` (там токен DuckDNS) и `vless-link.txt` создаются с правами `600`. Не публикуйте их — они уже в `.gitignore`.
- Куда обращается скрипт, кроме ваших серверов: DuckDNS (обновление адреса), Let's Encrypt (сертификат), репозитории пакетов Debian/Ubuntu и Cloudflare (WARP), GitHub (загрузка Xray и списков; для одного российского сервера — запасные зеркала ghproxy.net и gh-proxy.com). Самопроверка открывает через VPN cloudflare.com, speed.cloudflare.com и 2ip.ru. Никакой статистики и телеметрии нет.
- Ключи хранятся только на серверах, в `/root/.vless-setup/`.

## Разработка

```
src/
  wizard.sh          мастер (запускается на компьютере пользователя)
  server/entry.sh    сервер-вход в схеме из двух серверов
  server/relay.sh    зарубежный сервер в схеме из двух серверов
  server/single.sh   схема из одного сервера
  lib/               общие части: порты, nginx, сертификат, сайт-заглушка, WARP, панель
tools/build.py       сборка одного файла dist/vless-setup.sh
tests/e2e.sh         сквозные тесты мастера на имитации серверов
tests/validate-configs.sh   проверка всех вариантов конфигов настоящим Xray
```

```
make build      # собрать dist/vless-setup.sh
make lint       # shellcheck
sudo make test  # сквозные тесты (лучше в контейнере: создают системного пользователя xray)
make validate XRAY_DIR=/путь/к/каталогу/с/xray   # конфиги настоящим Xray
```

Готовый `dist/vless-setup.sh` в репозиторий не коммитится. CI собирает его на каждый тег `vX.Y.Z` и прикладывает к релизу вместе с контрольной суммой. Номер версии берётся из файла `VERSION`.
